# 六人模式评估（2026-10-08）

结论：本轮不加入六人选项，保留四人。维护目标是新增拓展独立可选、尽量少修改上游核心；目前六人模式不满足这个条件。

来源莱茵 fork 早期提交 `90be1ed7ae8d131b0142be923b75693a26e0bd61` 实现六人合作，并在 `cd09d57771f1d3ded43e3330ee47ace2de338130` 调整六人禁选、Boss 血量及回合补给。它采用全局最大席位及配套规则，不是现成的「建房前选择四/六人」插件。引用仅用于评估，没有作为本轮六人功能移植。

需要适配的部分包括：

- 大厅建房容量字段、服务端每房间席位上限、权限和房间状态协议。
- 等待室卡片、策略选择、队友面板、Boss/联防参与者及重连消息容量。
- 六人共享池与开局禁选、领袖血量、对局配对及来源的额外补给选择。
- 六人和四人同时运行时的隔离，以及全部可选拓展、AI、掉线/补位和资料切换回归。

目前 `MAX_SEATS` 是四人的全局常量，多处系统读取它。直接改为六会影响所有房间；增加动态容量则需要改动上游核心。来源首次六人实现涉及 32 个文件（含文档、测试），后续还持续修改平衡规则。与当前官方 0.2.1 的联防、补位和存活人数 Boss 规则结合时，需要逐次验证，无法承诺只维护一个内容模块。

当前八项拓展继续各自默认关闭、独立开关。工具包用补丁与资料生成器构建候选，不宣称是运行时 Mod 加载器。若上游以后提供房间容量接口或稳定插件钩子，再重新评估六人作为独立选项；本次不增加占位按钮。
