# 0.3.1：八个功能，八个插件

继续使用同一个仓库，插件源码在 `plugins/lele-*/`。每个插件有独立清单、版本、数据、来源说明与上游工具生成的锁文件，可分别打包、安装、选择和移除。所有玩法默认关闭；房主在等待室插件面板选择，勾选仅暂存，完成后点击“加载所选插件”统一应用；关闭面板也会提交待选配置。显示“正在启动插件…”和原生下载校验进度，应用请求单独等待最多60秒，失败在面板持续显示原因并保留选择以便重试，不会悄悄使用旧配置开局。其他玩家下载并校验同一内容，重新准备后开局；开局后锁定。

## 兼容边界：目前需要本仓库宿主适配

这些是**需要 Lele 宿主 API 1 的插件**，不是纯原版 0.3.1 即装即用插件。上游 API 1 还没有开放完整的科研面板、魂灵身份、收藏品选择/复活与跨战场敌人转移等入口。为保留现有玩法，本包仍包含固定基线的宿主补丁。

宿主适配集中在 `patches/modpack-code.patch`：扩展引擎和界面、注册已实现的特质、将选定插件的功能数据组成房间内容，并从同一数据快照冻结对局开关。没有开启插件时不注入该功能数据。插件本身通过官方清单、检查、打包、安装、房间选择、内容哈希、下载和重连链路工作，不运行任意宿主脚本。

原版宿主缺少 `config.economy.leleHost` 路径时，检查器会报 `PLUGIN_PATCH_PATH`，阻止启动残缺玩法。不要删除该检查来强行安装。普通第三方插件继续使用上游校验，不放宽通用数值上限；本包显式声明由宿主已经实现的战斗特质。

共享引擎目前随宿主构建，不随每个小插件重复携带；所以移除某个插件会关闭对应内容，但不会从已构建宿主中物理移除对应引擎代码。后续上游开放接口后，可以逐项缩减这一层，不需要再造一个加载器。

## 安装和更新

首次使用先按 [部署说明](DEPLOYMENT.md) 构建适配宿主；构建会安装八个插件，仍全部默认关闭。已有适配宿主可以单独安装：

```bash
node scripts/install-plugins.mjs /abs/game lele-factions lele-relics
```

省略插件 ID 则安装全部。安装器只管理指定的 `lele-*` 文件夹，不覆盖 `.env`、其他作者插件或 `plugins/config.json`。已有对局时不要修改它们所用的插件，先在独立候选目录更新。

发布版每项提供独立 zip；整套压缩包只是把八个插件放在一起，解压到适配宿主的 `plugins/`。不要把整套包当作一个插件 zip 导入上游安装器。单个 zip 可使用上游 `node tools/plugin.mjs install /path/to/lele-xxx-0.3.1.zip`。

插件工作台 `/studio/` 沿用上游的本机/LAN访问规则；远程管理可用 SSH 端口转发，不开放公网工作台。玩家直接使用普通游戏链接，在房间的“插件”中查看介绍、勾选。

## 后来者与 Agent

优先阅读 `AGENTS.md`、本页和 `upstream.lock.json`。上游插件规范见官方 `docs/PLUGIN-API.md`，本仓库额外宿主约定只有 API 1。不要把官方 API 和本包兼容层混称为一个稳定协议。

改数据后用 `scripts/build-plugins.mjs GENERATED_SOURCE OUTPUT` 从固定生成结果提取功能差异；它是维护工具，不是运行时依赖。最终使用官方 `check --strict`、`pack --zip` 生成锁和包。重做宿主适配后检查八项单开、主要组合、等待室更改、校验门、开始与在线重连；不宣称支持跨重启恢复。
